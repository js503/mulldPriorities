Selected interface: Clear Bands → Preset with rules → Icon group → Proposed numbers. The KPIs remain visible above the three tabs, preset controls and review row; the real Work grid stays underneath.

## Functional coverage

The current configuration requests and loads **99 mod entries** and exposes **26 visible work types**, including OgRepairGearType. The existing assignment audit exercises Everyone/Off, actual apply and undo for every eligible work type in both staffing policies. This establishes assignment compatibility for this list; it does not claim that every work giver can complete its jobs under all bills, equipment or pathfinding conditions.

Additional checks cover:

- Named save, trimmed/case-insensitive names, 40-character/control-character validation, new-store/library reload, duplicate names and confirmed overwrite.
- No commit before overwrite confirmation; canceled overwrite retains the old rules. The actual compact confirmation button path commits the replacement.
- Built-in names can be locally overridden; factory rules can still be loaded without deleting that override.
- Library reads reject malformed/duplicate/DTD input and do not silently replace a damaged file; atomic writes preserve the old file on validation failure.
- Missing mod work is skipped when loading but remains in stored definitions when another preset is saved.
- Presets retain policy, primary-job limit and focus flags without capturing exclusions, locks, temporary boosts or automation settings.
- Clean/Harvest/Haul project priority 1 for all available eligible managed workers even when the primary-role budget is full. Protections remain effective.
- Preview exposes staged numbers while real GetPriority values remain unchanged. Clicking a staged cell updates current → proposed inspection only.
- Collapse hides preview drawing and preserves the draft; expanding restores it. Rule changes invalidate the draft and mark the preset modified.
- Save callbacks reject changed rule snapshots. Enter submits the name entry; overwrite requires its own explicit confirmation. Map name/dirty/focus settings survive save/reload.
- Existing stale-plan, numbered-priority consent, protected undo, boosts, AutoPriorities overlap and diagnostics-default tests remain enabled.

Standalone results: **44 planner checks + 7 diagnostics checks + 13 named-preset checks passed**. Planner validation includes 200 policy scenarios and 500 exact comparisons with the pre-optimization algorithm.

## Large colony

The same disposable fixture contains 100 actual spawned colonists, 39,747 map things, 4,001 haulables and 2,000 ready crops. With the current 99-entry mod list and 26 work types, the 64-sample warmed benchmark measured a **1.426 ms median plan** and **0.145 ms average review-extension Repaint** (120 repaint samples). Full timings, p95/worst, allocations and diagnostics on/off measurements are in ProposedNumbers/performance.json.

These are paused-simulation operation timings, not overall TPS/FPS or a per-mod CPU percentage. Native work-table and other mods' rendering are excluded from extension timing. Scheduling noise from other running applications affects timing tails. No forced GC is used. The fixture is an isolated copy; nothing is generated into the normal save.
